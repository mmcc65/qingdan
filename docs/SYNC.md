# 云同步实施方案

## 当前状态

第一版云同步已经接入并通过 Windows 与手机实机验证。所有编辑先写入本地；登录后应用会执行首次同步、自动推送并订阅实时变化。当前版本以“每个用户一份完整状态文档”为同步单位，复杂冲突的逐实体或分字段合并仍属于后续工作。

## 数据同步原则

- 本地优先：所有编辑先写入本地，断网仍可使用。
- 状态同步：任务、项目、重复规则和历史事件作为一份完整状态写入当前用户记录。
- 设备标识：每台设备拥有独立 ID，用于排查同步来源。
- 更新时间：本地状态携带更新时间戳，云端记录同时保存 `updated_at` 和修订号。
- 冲突处理：首次连接优先读取已有云端状态；后续比较本地与云端时间戳，采用较新的完整状态。当前不进行字段级合并。

## 当前同步内容

每个账户在 `qingdan_entities` 中使用一条主记录，其 `payload.state` 包含：

- 待办和重复任务
- 重复任务事件（完成本次、跳过本次）
- 项目、子项目和项目任务
- 各项状态、节点、备注与提醒配置

数据库结构保留了实体类型、修订号、父级和软删除字段，供后续逐实体同步演进使用；`0.5.2` 客户端尚未启用这套细粒度同步方式。

## 用户需要提供

1. 创建或选择一个云数据库项目。
2. 提供项目公开地址和客户端匿名公钥；不需要提供账户密码或服务端管理密钥。
3. 使用邮箱和密码注册或登录。

云端表必须启用按用户隔离的行级权限，确保一个账户只能读取自己的数据。

数据库迁移文件位于 `infra/supabase/migrations/001_initial_sync.sql`。应用更新文件桶是独立的可选能力，不应与用户数据同步地址混为同一个信任边界。
