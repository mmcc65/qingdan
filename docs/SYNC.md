# 云同步实施方案

## 当前状态

第一版云同步已经接入并通过 Windows 与手机实机验证。所有编辑先写入本地；登录后应用会执行首次合并、自动推送并订阅实时变化。复杂冲突的分字段合并仍属于后续工作。

## 数据同步原则

- 本地优先：所有编辑先写入本地，断网仍可使用。
- 增量同步：只传输发生变化的任务、项目、重复规则和历史事件。
- 软删除：跨设备同步时删除操作先记录墓碑，避免离线设备把旧数据重新上传。
- 设备标识：每台设备拥有独立 ID，用于排查同步来源。
- 更新时间：实体保存 `created_at`、`updated_at` 和单调递增修订号。
- 冲突处理：不同字段可合并；同一字段冲突默认采用较新修订，并保留冲突审计记录。

## 当前同步实体

- 用户账户
- 设备
- 待办任务
- 重复规则
- 重复任务事件（完成本次、跳过本次）
- 项目
- 项目任务
- 删除墓碑
- 同步游标

## 用户需要提供

1. 创建或选择一个云数据库项目。
2. 提供项目公开地址和客户端匿名公钥；不需要提供账户密码或服务端管理密钥。
3. 使用邮箱和密码注册或登录。

云端表必须启用按用户隔离的行级权限，确保一个账户只能读取自己的数据。

数据库迁移文件位于 `supabase/migrations/001_initial_sync.sql`。应用更新文件桶是独立的可选能力，不应与用户数据同步地址混为同一个信任边界。
